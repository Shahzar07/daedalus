## When to use
The user wants prose produced — and often saved — rather than a quick chat answer.

## Steps
1. Pin down audience, purpose, tone, and length. Ask only if a wrong guess would waste effort.
2. Draft with a clear structure (title, sections, a strong opening and close).
3. Read it back once for clarity and cut filler.
4. If the user wants a file, `files_write` it (e.g. Markdown) and report the path.

## Notes
- Match the requested voice. Prefer plain, concrete language over padding.
